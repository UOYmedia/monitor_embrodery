## Scope of this batch

The user's request: build a test/plan that extracts **all** information the
Dahao BECS-A15 embroidery machine can provide, **fully automatically, with no
human standing at the machine's control panel (HMI)**.

The decisive protocol fact that shapes the whole batch (from recon of the vendor
`DesignServer.exe`): the emCAD MQTT protocol has **no server-initiated query
topic** — every server→machine message is a reply/ack to something the machine
started. So under "no operator," the machine's information surface is exactly
what it emits on its own: the connect/auth handshake (identity) and the periodic
`state` heartbeat (the rich telemetry). Plan 001 builds an enumerator that
captures that surface exhaustively into a `catalog.json` + `enum.log`, and runs
a small safe probe that empirically confirms nothing more can be pulled.

## Findings considered and rejected (so nobody re-audits them)

- **Pattern browse/query/download/upload topics** as an information source: they
  exist, but the machine only initiates them when an operator opens the
  network-pattern screen on the HMI — excluded by the "no operator" constraint.
- **Server-push to force the machine to send more**: does not exist in the
  protocol (no server-initiated topic). Plan 001's probe verifies this rather
  than re-investigating it.
- **EmbNet/SEMS protocol** (`SemsServer.exe`/`SemsClient.exe`, a different,
  richer DaHao telemetry protocol): three prior pieces of evidence indicate the
  A15 does not speak it. Deferred as a separate spike, not part of this batch.
